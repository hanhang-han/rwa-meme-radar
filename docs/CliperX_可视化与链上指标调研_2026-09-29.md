# CliperX 可视化与链上指标调研

日期：2026-09-29。交付：产品研究、指标定义和交互概念稿；未修改线上网站。

**建议把首页做成“股票主题行情地图＋重要变化流”，详情页增加“谁在参与、参与是否持续、筹码是否集中”的解释。** 首期先用现有数据形成辨识度，再补充地址分析。好看的图负责让人发现对象，有依据的变化负责让人继续研究，关注功能负责让人回来。

本次将 FOMO 理解为 [fomo.family](https://fomo.family/)。研究依据为竞品官方介绍、开发文档、当前项目代码和最近的健康修复记录。浏览器现场访问未成功，因此竞品描述依据官方材料，不声称完成了登录后体验；本项目布局结合当前 `LiveView.vue` 和 9 月 25 日验收截图判断，不将旧截图数字当作今天的行情。下文明确区分竞品事实、设计建议及待验证能力。

## 1. 竞品真正值得借鉴的部分

| 产品 | 已核实的做法 | 对 CliperX 的启发 |
|---|---|---|
| Crypto Bubbles | 每个气泡代表币；尺寸、颜色、内容可按表现、市值、成交额等配置；支持列表、收藏、点击看详情及拖动碰撞 | 把扫描很多行数字变成一眼找异常；图与表必须能互切，点击后要有下一步 |
| FOMO | 成交动态、交易者资料、关注提醒、分时段榜单，以及交易观点与仓位上下文 | 用户关心“谁发生了什么、之后怎样”，需要可连续追踪的故事 |
| Bubblemaps | 气泡代表持币地址，连线代表转账；可展开中间地址并查看历史分布 | 用图解释筹码结构，适合放到单币详情页 |
| DEX Screener | 当前 API 包含主题 metas、广告、boost、社区接管及交易对数据 | 主题发现和推广行为可成为研究背景；广告热度要与交易活动分开 |

来源：[Crypto Bubbles 官方应用介绍](https://play.google.com/store/apps/details?hl=en&id=net.cryptobubbles)、[FOMO 官方 Web 介绍](https://fomo.family/blog/announcing-fomo-web)、[Bubblemaps 图形含义](https://wiki.bubblemaps.io/bubblemaps-v2/how-does-it-work)、[DEX Screener API](https://docs.dexscreener.com/api/reference)。

Crypto Bubbles 官方商店页面显示 Android 下载量 100 万以上，说明这种呈现方式具有使用规模；但这不能证明增长全部由视觉导致。我的产品判断是：它把“找变化”变得轻松、可玩、适合截图传播，这比单纯增加动画更值得学习。

**Crypto Bubbles 和 Bubblemaps 是两类图。** 一个比较币与币的行情，一个分析同一币的持币地址。首页不能让同样的气泡有时代表币、有时代表地址，却没有明确切换。

FOMO 的社交内容来自其平台账户、真实成交和用户自己写的观点。CliperX 目前不能凭链上地址还原这些人的身份或理由。可以先做“关注主题／资产／地址的变化流”，以后再考虑用户投稿；系统生成的事实解释应标为系统摘要，不能包装成交易者发言。[FOMO 官方社交功能说明](https://fomo.family/blog/learn/leveraging-fomos-social-features)

## 2. 对当前页面的判断

当前首页依次是四个汇总数字、今日异动、热门股票卡片、实时成交、新发现、成交榜和各链对照。已有发现和实时更新基础，但主要依赖卡片、数字和列表，视觉重心分散。

用户要判断“哪个主题出现变化”，仍需要自己把股票卡片、Meme 排名和成交串起来。逐笔成交在动，也不一定能解释变化是否值得继续看。

本轮应在 9 月 21 日展示研究的基础上增加三件事：

1. **一个明显的视觉入口。** 把股票主题与 Meme 放到同一张可探索的图里。
2. **有延续性的事件。** 从“某笔买了多少”发展为“首次活跃→活动增加→是否持续→筹码变化”。
3. **能解释参与结构的新指标。** 从价格、成交额发展到新增买入地址、持续持有、地址关联和可交易深度。

不需要为每个指标新开一个一级栏目。首页负责发现，股票主题页负责比较，资产详情负责解释，关注页负责追踪。

## 3. 首推的视觉方案

### 3.1 股票主题行情地图：作为首页主视觉

首屏结构建议：标题和搜索 → 紧凑统计条 → 行情地图（约 2/3 宽）＋所选对象摘要（约 1/3）→ 重要变化流。长简报折叠，原始逐笔成交放到“全部成交”子视图或详情页。

**一颗气泡代表一个链上资产，一个分区代表一个股票主题。** 英伟达、特斯拉等作为主题标题，明确这是关联 Meme 的行情，不是原股涨跌。

| 视觉元素 | 首版定义 |
|---|---|
| 分区 | 股票主题；默认优先已核验配对，名称线索单独切换 |
| 气泡面积 | 合格资产的 24h 成交额；面积而非半径与数值对应 |
| 颜色 | 同一时间窗的涨跌幅；色阶固定，不能每次刷新重新归一化 |
| 文本 | 简短名称＋涨跌百分比；点击后显示中文全名、链与短合约 |
| 侧栏 | 为什么收录、变化是什么、规模、数据时间、查看证据、加入关注 |
| 动画 | 新事实到达后短暂突出变化；选择、拖动及布局过渡有反馈 |
| 灰色状态 | 行情过期或缺失，保留最后有效时间；不渲染为平盘或 0 |

第一版不采用复杂的“涨幅＋市值＋买家数＋风险＋关系强度”多重视觉编码。尺寸和颜色各解释一个东西，其他信息放侧栏。

默认 30–50 个合格对象，手机 12–20 个；这是试验范围，不是性能结论。固定主题区域和稳定位置，切换时间窗后保持对象可追踪。大额成交可能把其他气泡压得不可读，可切换“等大”模式；如果做尺寸截断，图例必须说明，悬浮展示真实值。

多主题资产在总览只画一次，选择明确的主展示主题并标“另有 N 个主题”；主题详情可重复出现，但全站汇总去重。同名、跨链合约不因符号相同而合并。

提供表格模式、键盘选择、减少动态效果选项。分享图带有主题、时间窗、口径和数据时间，避免截图失去上下文。

### 3.2 活动与涨跌四象限：比单纯涨幅榜更有判断价值

横轴为价格涨跌，纵轴为成交活跃程度相对于历史基线的变化；气泡大小为同范围流动性。适用于已积累完整成交桶的重点资产。

四个区域用直白名称：“放量上涨”“放量下跌”“缩量上涨”“缩量下跌”。中性区独立显示。标题不能叫“机会区／危险区”，因为这只是观察事实。

它回答的是：这个币涨了，是否同时有更多交易？价格剧烈波动是不是发生在很浅的市场？点击后沿用行情地图侧栏，不另建一套详情。

### 3.3 主题扩散时间线：体现 CliperX 的特色

在股票主题页展示：最早观察到关联 → 新增池配对证据 → 出现持续成交 → 更多关联资产开始活跃。用户可回放指定时间段，查看主题是集中在一个币，还是扩展到多个对象。

时间线必须区分“链上发生”和“本站发现”。历史补采不应制造今日新热点。股票新闻若没有可靠事件源，先不加入“新闻引发上涨”等解释。

### 3.4 持币地址关系图：放到详情第二层

适合回答“前十大地址看起来分散，是否存在转账联系”。优先展示少量重要簇，点击展开证据及排除项，避免默认给用户几百个无法理解的点。

连线代表观察到的联系，不直接证明同一人控制；交易所、桥、LP、销毁地址等要单独处理。Bubblemaps 的 Magic Nodes 会增加非当前持有人等中间节点，帮助解释间接关联，这可以作为交互参考。[Magic Nodes 官方说明](https://wiki.bubblemaps.io/bubblemaps-v2/magic-nodes)

## 4. 值得做的新指标

以下是我们的设计建议，均须先通过口径与数据覆盖验收。“有基础”不等于今天已经可以准确发布。

| 页面名称 | 用户能得到什么 | 定义及主要门槛 | 所需投入 |
|---|---|---|---|
| **成交突然活跃** | 找到刚发生变化的对象 | 最新完整 5m 成交额／之前 12 个完整 5m 桶中位数；同池或同资产范围一致，基线过低时只写“恢复活跃” | 已有成交/K 线基础，补覆盖校验及基线聚合 |
| **主题一起涨了吗** | 分辨一币独涨和主题共同变化 | 同一固定合格集合中，上涨、下跌、持平的数量及比例；未知单列，并给有效数／总数 | 现有关系和报价可加工，先不称行业指数 |
| **新增买入地址** | 是否有新的参与者进入 | 窗口内买入、且完整回看期内未观察到买入该币的地址数；建议回看 30 天，历史不足时标“本站首次观察” | 补真实参与地址、回看历史、地址角色 |
| **买后仍持有** | 新进入者是否很快离开 | 某日首买地址群体，在首买 24h 后仍持有超过公开尘埃阈值的比例；只纳入已经满 24h 且余额可核查的样本 | 持仓检查、Transfer、完整队列；显示有效样本和覆盖 |
| **早期买入者动态** | 早期地址现在持有、卖出还是转出了 | 依据可验证开池时间定义首小时群体；分别统计持仓减少、DEX 卖出、转出；不能把转出直接算获利退出 | 历史交易＋转账＋地址归属，第三阶段 |
| **关注地址在买什么** | 用户可以跟踪自己感兴趣的研究对象 | 自选地址、明确来源标签、买卖与持仓变化；同时可查看卖出、失败和观察缺口 | 定向地址采集，先不做全网赢家排行榜 |
| **关联地址持仓** | 看清表面分散背后的联系 | 独立显示原始 Top 10 和剔除基础设施后的地址簇持仓；公开聚类依据和版本 | Bubblemaps 试验或自建转账图 |
| **指定金额的价格影响** | 大涨的币是否其实很难成交 | 固定方向、明确市场、指定金额的询价结果；展示报价时间、路由、费用和价格影响 | 额外报价能力及缓存，不能用 TVL 直接推算 |
| **新增／撤出流动性** | 区分价格涨导致估值上升和实际 LP 操作 | 解码对应池协议的加减流动性事件，分开手续费领取、头寸变化和估值影响 | 协议级事件解析，不从 TVL 差值猜测 |

首期建议只发布前两项；新增买入地址先做限定范围试点。其余作为详情层分阶段增加，避免再次出现一屏没有值的指标。

**新增地址不是新增用户。** 一人可以用多个地址，路由器可以代很多人交易；EVM 交易发起者也可能是账户抽象的 bundler。需要结合转账归属、路由解析及账户类型识别，无法归属时排除并显示覆盖。

当前链 Swap 写入路径保存了池、交易哈希、区块、时间和数量，但这条路径没有直接补齐最终交易者身份。因此买入地址、赢家画像、持有周期不能简单对现有成交行分组就上线。参考代码：`server-py/app/collectors/chain_stream.py` 中调用 `commit_trade` 的链上成交写入路径。

“买后仍持有”只能说明该地址的后续余额，不能证明同一批币完全没有卖出或后来买回；若要分析原始买入份额的留存，需另建有明确成本分配方法的仓位账本。

## 5. 从 FOMO 借鉴怎样的变化流

每条变化卡采用固定结构：**对象＋发生的事实＋比较基准＋发生时间＋证据＋关注操作**。重要性按公开条件排序，不使用无法解释的综合“推荐分”。

示例仅用于说明结构，不是线上事实：

> 英伟达主题 · 示例资产 A
> 最近完整 5 分钟成交为过去一小时典型水平的 3.2 倍。
> $32,000／基线 $10,000；13 个完整桶；查看统计池及原始成交。

> 示例资产 B · 新买入参与面扩大
> 本窗口新增 28 个可识别买入地址；此前 30 天回看完整。
> 地址归属覆盖 92%；查看地址与排除项。

> 特斯拉主题 · 新增配对证据
> 本站首次核验一个股票代币配对池。
> 分别显示池创建时间和核验时间；查看链上证据。

默认显示“我关注的”和“重要变化”，原始成交为可切换视图。一个对象在短时间反复触发时合并卡片，保留展开记录。用户在向下阅读时显示“新增 N 条”，不要顶走当前内容。

对信号保存首次发布时间及当时指标，后续展示 1h／24h 表现与是否仍活跃。失败、回落、证据撤销的信号同样保留。这样可以逐步回答“本站给出的变化提示，后来怎样”，形成可核查的产品价值，而不是只展示后来涨了的案例。

短期不建议开发完整社交网络、收益排行榜和跟单交易。这些需要身份、全量历史、成本与收益口径、内容治理，投入远大于一个变化流。先做关注对象和事件回访就能验证用户需求。

## 6. 数据从哪里来，哪些可以接

### 6.1 现有数据优先复用

行情地图、主题广度和关系时间线优先用现有统一报价、关系证据、事件和关注能力。数据库聚合结果统一供图表、列表与简报使用，前端不要重复计算不同版本的热度。

继续保持已约定的五分钟基础采集和调用预算。新的页面切换、排序、动画不触发新一轮上游采集；已有流式成交能提供真实更新时，通过现有推送链路同步。

### 6.2 Bubblemaps：最值得先做覆盖试验

官方提供两种产品：可嵌入的图，以及可自行展示的地址、转账、聚类数据 API。[官方 B2B 介绍](https://docs.bubblemaps.io/introduction)

本次查到的支持链文档枚举包含 `bsc`、`robinhood`，未看到 `xlayer`；这只是文档范围，不保证任意币已有地图。下一步必须对实际目标合约做样本测试，不能仅因为链被支持就承诺覆盖。[支持链接口](https://docs.bubblemaps.io/data/api/chains/supported)

指标接口包含调整后的 Top 10、地址簇、fresh wallets 等。官方把 fresh wallet 定义为小于 10 天，与我们的“首次买入该币地址”不同。返回占比为 0–1，需要正确转成百分比；不能直接照抄字段名给用户。[指标接口定义](https://docs.bubblemaps.io/data/api/tokens/metrics)

该接口文档标注每次 25 credits。以 30 个币每小时一次估算：720 次／天、18,000 credits／天；若每五分钟一次则是 216,000 credits／天。实际美元费用、地图更新时间、缓存及网站/API 展示权限需按方案确认。筹码结构首版按小时检查，比追求秒级合适。

线上 iFrame 需要正式 partnerId 和域名白名单；`demo` 仅用于文档规定的本地环境。分析平台适用商业合作方案，不能把用户版可访问理解成可以免费嵌入。[嵌入条件](https://docs.bubblemaps.io/iframe/pricing)

### 6.3 DEX Screener：扩充主题和外部背景

可试验 metas 主题目录与趋势、广告／boost、社区接管数据，与我们已有股票主题做合约级交叉匹配。它们能补充“这个币最近被如何推广、被归入哪些叙事”，不能直接当作买家增长或真实资金进入。其主题 API 当前标注 60 次／分钟，这只是上限，我们仍应缓存和限额。[官方 API](https://docs.dexscreener.com/api/reference)

### 6.4 Nansen：研究有启发，公开展示需按端点判断

官方提供按地址类别划分的持仓、成交与流向接口，BNB 在其支持范围内；本次查阅的 Smart Money 链列表未列出 X Layer 或 Robinhood。[Smart Money 文档](https://docs.nansen.ai/api/smart-money)

但其再分发指南对地址标签、Smart Money 成交、部分排行榜等有明确限制，不能默认拿来展示或转供我们的 API。普通成交／部分流向端点与专有标签端点的要求也不同。适合先评估允许的功能和商业条件，不作为首版“聪明钱跟踪”的默认数据源。[再分发指南](https://docs.nansen.ai/guides/redistribution-guide)

### 6.5 Birdeye 与 FOMO

Birdeye 有行情流和地址分析能力，但具体端点的链支持不同；例如本次查阅的 Smart Money Token List 发布说明只列 Solana，不能因它支持多链行情就假定所有钱包分析覆盖我们的三条链。[官方更新](https://docs.birdeye.so/changelog/20260206-release-megaeth-support-smart-money-api)

FOMO 本轮作为产品交互参考。本次没有核实到可用于 CliperX 生产展示的官方公开社交数据 API；搜索中出现的同名第三方 API 不能视为官方授权。首版不依赖抓取 FOMO 的用户资料、榜单或观点。

## 7. 加工与更新：不要把新指标放进现有写入瓶颈

9 月 28 日健康修复记录仍有链日志积压和历史缺口。本轮未重新做生产健康验收，因此这里只把它作为设计前提：**近期成交可能更新，完整历史统计仍需单独证明。**

推荐链路：原始事实与来源 → 去重和回滚处理 → 1m／5m 聚合桶 → 指标快照与事件 → 页面增量推送。指标任务在后台限额处理，图表请求只读已经生成的结果。

每个指标至少包含：对象 ID、值、单位、时间窗口、数据发生时间、统计时间、来源、覆盖、方法版本和缺失原因。历史补采修正统计后应发“历史修订”，不伪装为刚发生的事件。

| 内容 | 建议更新方式 | 页面含义 |
|---|---|---|
| 最新成交／报价 | 随可信上游事件增量同步；无流则沿用预算内采集 | 有真实变化才强调；显示最后市场时间 |
| 5m 活跃程度 | 完整桶关闭后计算；形成中数据单独显示 | 可以比较同样长度的完整窗口 |
| 买入地址、主题统计 | 后台约 1–5 分钟聚合，视覆盖发布 | 时间范围和覆盖可查 |
| 集中度／筹码图 | 小范围按小时检查，遵守来源实际刷新频率 | 不标秒级实时 |
| 24h 持有率 | cohort 成熟后生成并定期修订 | 未满观察期显示“观察中” |

必须保持：未知不等于零；滚动 24h 成交额差不能当作 5m 成交；TVL 增加不能直接称资金净流入；同名不能替代合约身份；股票休市与行情延迟分开；收到推送不能替代数据新鲜度。

近期先对 30–50 个重点对象做指标投影，不对几千个对象每次刷新都扫历史。完整采集日志与长历史统计要有独立资源预算，避免新可视化拖慢价格和 API。

## 8. 实施顺序与验收

| 阶段 | 交付结果 | 发布门槛 |
|---|---|---|
| 第一阶段：视觉入口 | 股票主题行情地图、表格互切、详情侧栏、关注入口、重要变化流 | 可复用现有合格数据；同一对象图表与列表一致；未知和过期可理解；手机与中英文可用 |
| 第二阶段：行为解释 | 成交活跃程度、主题广度、限定地址参与面、信号后续结果 | 去重、时间窗、断线补采与重组校正通过；有覆盖才能发布；不增加既有 OKX 预算 |
| 第三阶段：筹码结构 | Bubblemaps 试验、持有持续性、早期地址动态、真实 LP 变化 | 样本合约有数据；费用与展示权限明确；地址归属和历史完整性达标 |

第一阶段不必等待所有地址数据补齐，能先建立明显的视觉改善。第二、三阶段可以在小范围运行，达到发布条件后再扩大覆盖。

建议先选 5 名目标用户做任务测试：不讲解的情况下，能否在 30 秒内指出一个正在变化的股票主题，并在 60 秒内找到对应资产和依据。成功率 80% 作为初版目标，属于待验证产品假设。继续跟踪地图到详情点击率、关注转化、7 日回访和事件查看率，不能只看页面停留时长。

数据验收另外记录：指标可发布覆盖率、真实事件延迟、重复事件比例、历史修订次数、每个有效对象调用成本。视觉演示通过不等于这些指标通过。
